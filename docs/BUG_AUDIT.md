# Bug audit — v0.3.0-preview.4

This pass reviewed the dock, monitor/appbar lifecycle, Finder navigation and file operations, tabs/split panes, Shelf and workspace storage, icons/process identification, menus, wallpaper library, update helpers and settings backends. It preserves the original glass renderer and the previous monitor/Shelf fixes. The custom desktop experiment remains reverted.

## Confirmed issues corrected

| Area | Problem and correction | Verification |
|---|---|---|
| File drops | Finder could move originals offered by a copy-only source. Copy/move selection now respects allowed operations, modifiers and drive boundaries, and the advertised effect matches the operation. Unsupported link gestures are rejected. | Copy-only file drop preserves the original and creates the correct destination; modifier/cross-drive checks. |
| File destinations | Folder drops temporarily changed the browser's navigation path during Windows file dialogs. Destinations are now explicit, and recursive folder transfers are rejected. | Actual fixture copy and navigation-path check; recursive-transfer rejection. |
| Directory navigation | Old entries remained actionable while the next directory loaded. Loading clears the previous listing and selection immediately. An unavailable starting folder falls back to home; history skips removed folders and duplicate current locations. | Immediate navigation checks, removed history folder and missing-start fixture. |
| Folder refresh | File contents/size changes were not watched, and refreshing discarded selection. Metadata changes now refresh and restore matching selections. | Modify a selected file and verify its updated size and retained selection. |
| Finder workspace | Focusing the right pane could replace the selected left tab; closing a background tab could steal focus. Focus and displayed tab are now tracked separately, including keyboard focus. | Split-pane and background-tab-close checks. |
| Window ownership | Split view could move an existing Finder to the monitor of the last-used dock. Maximize padding affected only the original pane, and embedded close buttons behaved inconsistently. | Own-monitor split check, whole-workspace maximize padding and containing-window close check. |
| Pane lifecycle | Closing the original tab retained its watcher; queued watcher events could restart disposed panes. Closed panes now stop/unsubscribe and ignore late events. | Closed-tab watcher/timer checks. |
| File arguments | Open With paths containing spaces were not quoted; trailing directory separators could escape a closing argument quote. | Shared Windows file-path quoting and a real child-process argument round trip. |
| Menu commands | Finder commands could target the previously focused external app. Commands now track active OpenDock windows, and delayed key delivery checks focus before sending. Closed menu-bar windows release subscriptions and timers. | Finder command-target check and existing internal-window lifecycle tests. |
| Icons | One failing icon subscriber could block others; an old asynchronous result could overwrite newly selected artwork. Requests now isolate subscribers and use per-item generations. Process executable paths no longer persist across PID reuse. | Failing subscriber and queued-old/cached-new artwork checks; process lookup review. |
| Wallpaper library | Different photos with equal filenames/sizes could be confused. A prefix-only ownership check could delete a file in a similarly named personal directory. Copies now match contents; deletion is limited to direct library children. | Different same-size/name files, repeat import and preservation of a personal sibling-directory photo. |
| Shelf | A failed save could leave an added/removed/pruned collection in memory despite unchanged disk data. File-path casing could produce duplicates. Collection edits now commit transactionally and file deduplication follows Windows casing. | Locked-file failures for add/remove, source preservation and casing check. |
| Workspace storage | Unreadable data could be replaced with defaults on a later save. Valid previous data is now recovered, the unreadable original is archived before writing, and saves are refused when neither copy is readable. Failed staging writes are cleaned up; subscriber failures no longer invalidate a completed save. | Corrupt current/backup fixtures, archive preservation, locked writes, staging cleanup and failing observer. |
| Scene restoration | Finalization reapplied old monitor layouts, discarding edits made during the restore. Synchronous cross-process positioning could also wait on a frozen app. Restore applies layouts once and uses asynchronous native positioning. | Concurrent layout edit and existing separate-process geometry restoration. |
| Preferences | Loading twice appended duplicate pins, hidden apps and wallpaper entries. | Save/reload/reload collection check. |
| Rollback | Executable compilation dates could select the wrong previous installation. Backup selection now uses installation timestamps; native backups receive a backup timestamp. | Deliberately conflicting file/install timestamps. |
| Release parsing | Large numeric preview identifiers were sorted as text; malformed versions could be accepted. | Numeric-overflow and invalid-version checks. |
| Update failure handling | A result-log write failure could try to undo a successfully running update. Logging is now best effort; immediate startup failure still restores the previous executable. Staging files are cleaned up on failure. Changing update channels during a check discards the stale result. | Isolated executable checksum, update, rollback, immediate-exit and unavailable-log checks; channel filtering tests and UI guard review. |
| Settings helpers | The timeout ran after a blocking stdout read, so a hung command could wait indefinitely. Output is now drained asynchronously with a bounded process wait. | Sleeping helper timeout and a 64 KiB output fixture. |

## Coverage

Run `build.bat check` for deterministic checks, `build.bat check --audit-ui` for focused Finder/icon checks, `build.bat check --updater` for isolated executable handoff, or `build.bat check --ui` for the complete desktop suite. Test settings, logs and workspace data use temporary storage instead of the user's profile.

Windows reported one connected 1920×1080 display for the final complete audit run. The existing two-display regressions remain in the suite, but the full updated batch still needs a run after reconnecting the second display. Mixed-DPI monitors, physical unplug/replug, alternate shells and individual third-party application protocols require the hardware/manual checks in [TESTING.md](TESTING.md). This report records verified fixes and reviewed guards; it is not a claim that every possible defect has been eliminated.
